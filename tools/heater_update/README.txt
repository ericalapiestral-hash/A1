Aquarium B 히터 도구 묶음 v1.2.1 / B 펌웨어 v1.2.0

v1.2.1은 PC 릴레이 점검 도구만 수정했습니다. B에 이미 v1.2.0을 설치했다면 다시 업로드하지 않습니다.
로그가 비어 있을 때의 DTR/RTS 해제, status 요청, 수신 바이트 표시와 정상 재시작 기능을 추가했습니다.
Heater-Relay-Check.html만 새로 열어 사용합니다. 자세한 절차는 Relay-Check-README.txt를 참고하세요.

현재 Aquarium 히터 핀은 GPIO18입니다. 저장소의 예전 B_board(히터GPIO27)와 다릅니다.
원본 펌웨어 분석과 현재 소스에서 GPIO18 역할을 확인했지만 실물 IN/COM/NO/NC 연결은 아직 확인되지 않았습니다.
코드만으로 실제 히터 연결·가열·온도·접점 상태를 확인했다고 주장하지 않습니다.

급수 수동, 순환 수동/자동, A 센서 통신과 LCD를 유지하고 heaterMode=0/1 및 상태 회신을 추가합니다.
기존 앱 v1.3.8의 수동 히터 버튼을 사용하므로 APK를 새로 설치할 필요가 없습니다.
수온 센서는 없으며 목표 온도·자동 온도 조절·heaterMode=2는 지원하지 않습니다.

[배선이 미확인인 현재 상태에서 시작]
1. 히터·급수·순환 등 모든 부하 전원 플러그를 뽑고 B보드만 PC USB로 연결합니다.
2. 기존 로그/백업 도구의 시리얼 연결을 종료합니다.
3. Aquarium-B-Heater-Update.html을 Windows Edge/Chrome에서 엽니다.
4. 급수는 [현재 B 설정 자동 유지], 히터는 기본 [잠금 유지]로 둡니다.
5. 기존에 저장한 원본 4MB B BIN을 선택하고 준비 확인 후 B COM5로 설치합니다.
6. 검증 완료 후 업데이트 화면 연결이 종료되면 Heater-Relay-Check.html을 엽니다.
7. 모든 부하 전원이 분리된 상태임을 확인하고 B COM5를 연결합니다.
8. 잠금 v1.2.0 상태를 수신한 뒤 LOW/HIGH를 눌러 어느 릴레이의 표시/작동 소리가 바뀌는지 확인합니다.
   점검 신호는 GPIO18만 바꾸며 최대5초 뒤 기존 HIGH로 돌아갑니다. 중지 버튼도 있습니다.
   HIGH 복귀는 히터 OFF 보장이 아닙니다. 모든 부하 전원 분리를 유지합니다.
9. 관찰 결과를 적고 점검 보고서를 저장합니다. GPIO18에 실제 히터 릴레이가 연결됐는지,
   접점 배선과 어떤 신호가 실제 정지인지 확인되기 전에는 히터를 활성화하지 않습니다.

[배선과 정지 신호를 확인한 뒤 활성화]
1. 모든 부하 전원을 뽑은 상태를 유지하고 점검 도구의 연결 종료를 누릅니다.
2. 업데이트 HTML에서 히터 정지 신호 HIGH 또는 LOW를 선택합니다.
3. GPIO18 IN 연결, COM/NO/NC와 정지 신호를 확인했다는 항목을 선택해야 활성화 설치가 가능합니다.
4. 같은 원본 BIN으로 다시 설치합니다. 현재 급수 설정은 검증된 B 이미지에서 읽어 유지합니다.
5. 기존 앱 v1.3.8을 Aquarium에 다시 연결합니다.
6. firmware=Aquarium-control-1.2.0, heaterManualSupported=true,
   heaterMode=0, heaterOn=false 및 pin18을 확인합니다.
7. 실제 히터 사용은 제품의 설치/침수 조건, 자체 온도조절·과열보호, 전력 회로 정격을 확인한 후 진행합니다.
   앱 ON은 계산한 출력이며 실제 히터 전류·가열 측정값이 아닙니다.

[동작]
- 설정된 히터는 부팅 OFF입니다. 수동 ON/OFF만 지원합니다.
- B가 BLE 연결 끊김을 감지하거나 E1을 처리하면 히터 ON 요청을 지웁니다.
  재연결 또는 E0 해제만으로 다시 켜지지 않고 사용자가 다시 켜야 합니다.
- 온도/수위 기반 히터 제어는 없습니다. 온도센서, 실제 전류·유량·접점 피드백도 없습니다.
- 급수와 순환의 기존 수동 상태 유지 정책은 바꾸지 않습니다.
- 잠금일 때 heaterMode/heaterOn=null, heaterManualSupported=false를 보냅니다.
  기존 앱에서 히터 버튼을 눌러도 명령은 거부되고 실제 적용 확인은 되지 않습니다.
- USB GPIO18 점검은 잠금 상태에서만 허용하며 BLE로 보낸 check18 명령은 거부합니다.
  히터가 활성화된 설정에서는 USB 점검 명령을 차단합니다.

[보존/복원]
앱0x10000만 쓰고 MD5를 확인합니다. A·부트로더·파티션·NVS·SPIFFS는 보존합니다.
기존 원본, 순환1.0.1, 급수1.1.0의 각 설정, 새1.2.0의 설정을 확인해 같은 B만 갱신합니다.
이전 급수1.1.0(급수 설정 유지), 순환1.0.1, 더 이전 원본으로 복원할 수 있습니다.
복원 전에는 히터 전원을 포함해 모든 부하 전원을 분리합니다. 이전 프로그램은 히터 제어/동작 정책이 다릅니다.
쓰기 실패 뒤 대상 기록으로 같은 B만 복원합니다. 브라우저 저장 제한 시 화면을 닫기 전에 복원하세요.

원본 BIN, NVS, 실제 보드 MAC은 배포에 포함하지 않습니다. 파일·로그는 브라우저 안에서만 처리합니다.
점검 도구는 원문 USB 로그와 사용자 관찰을 TXT로 저장합니다. 서버에 자동 전송하지 않습니다.
실제 USB/릴레이/히터 시험은 이 작업 환경에서 수행하지 않았습니다.
GPIO18 역할은 코드/백업 기준이며 실제 배선 확인은 현장 단계입니다.
