================================================================
 코드 설명 — 220V 펌프 교체 버전 (순환펌프 = 협신 UP200)
================================================================
대상 코드 : A_board/A_board.ino , B_board/B_board.ino ,
            UP200_pump/UP200_pump.ino (순환펌프 전용·독립 실행)
바뀐 점   : 순환펌프(펌프2)를 12V DC → 협신 UP200(단상 220V AC·20W)로 교체.
            펌프 전원코드의 활선(L)을 잘라 릴레이에 "직렬"로 넣어 제어.
작성 목적 : "왜 이런 식으로 코드를 짰는가" 설계 의도 정리
            (먼저 '12V_펌프2개_버전_코드설명.txt'를 읽으면 이해가 빠름)


[ 0. 가장 중요한 결론 ]
----------------------------------------------------------------
펌프2가 12V DC → 220V AC로 바뀌었지만,
"제어 코드(펌웨어) 로직은 거의 바꿀 필요가 없다."

  왜냐하면 ─
  ESP32는 릴레이의 IN 핀을 LOW/HIGH로 토글할 뿐이고,
  그 릴레이 접점이 실제로 무엇을(12V DC든 220V AC든) 끊고 잇는지는
  "하드웨어(배선)의 문제"이지 코드가 알 필요가 없다.

  즉, 바뀐 것은 대부분 "배선"이고, 코드는:
   - A보드: 변경 없음(센서가 그대로라서)
   - B보드: 펌프2 제어 로직 그대로(타이머 방식 동일)
   - 추가:  UP200_pump.ino — 순환펌프만 따로 굴리는 독립 타이머 코드


[ 1. A보드 (A_board.ino) — 왜 안 바꿨나 ]
----------------------------------------------------------------
- A보드는 "센서 측정 + 송신"만 한다. 펌프 종류와 무관.
- 순환펌프가 220V가 되든 말든 수온/조도/탁도/pH/수위 측정은 동일.
- 따라서 A보드 코드는 12V 버전과 100% 같다(바꿀 이유가 없음).
  · 굳이 손대면 오히려 검증된 코드를 흔드는 셈이라 그대로 둠.
  · (이전 파일의 A보드 설계 의도가 그대로 유효)


[ 2. B보드 (B_board.ino) — 펌프2가 220V여도 로직이 같은 이유 ]
----------------------------------------------------------------
(1) 펌프2 제어는 여전히 "릴레이 IN 토글"이다
    - 12V 버전: IO26 → 릴레이 CH2 → (접점) → 12V DC 펌프 ON/OFF
    - 220V 버전: IO26 → 릴레이 CH2 → (접점) → 220V 펌프(UP200) ON/OFF
    - ESP32 입장에선 둘 다 "IO26을 LOW로 만들면 펌프 ON"으로 동일.
    - 그래서 pump2Mode / circOn / circOff / drive() 코드가 그대로 작동.

(2) 순환을 여전히 "타이머(circOn/circOff)"로 둔 이유
    - 순환은 수위·온도와 무관하게 주기적으로 돌리면 되는 동작.
    - 펌프가 220V로 바뀌어도 "몇 분 켜고 몇 분 끈다"는 규칙은 동일.
    - 즉 제어의 본질(시간 기반)이 안 바뀌므로 코드도 안 바뀐다.

(3) 그럼 무엇이 실제로 달라지나? → "하드웨어/안전" 쪽
    - 릴레이 접점이 이제 220V 활선(L)을 끊고 잇는다(고전압).
    - 그래서 코드보다 배선·안전 규칙이 중요해진다:
        · 릴레이는 활선 L 만 끊음 → OFF여도 N(중성선)은 통전.
        · 릴레이 접점 정격 250VAC 이상 확인(UP200 20W라 여유 충분).
    - 이 내용은 코드 주석/문서(B_board_control_table.md,
      UP200_circulation_wiring.svg)에 반영해 둠.

(4) 시작 시 OFF / 통신 끊김 시 히터 OFF 등 안전장치가 더 중요해진 이유
    - 부하가 220V가 되면 오동작의 위험이 커진다.
    - 그래서 "부팅 시 전 채널 OFF", "drive() 극성 일괄 처리" 같은
      기존 안전 설계가 그대로(혹은 더) 의미를 가진다.


[ 3. UP200_pump.ino — 왜 "따로" 짰나 ]
----------------------------------------------------------------
(1) 순환펌프만 독립적으로 돌리는 전용 스케치로 분리한 이유
    - 220V 순환펌프를 B보드와 별개로 ESP32 하나에 올려
      "순환 타이머만" 단독 운용할 수 있게 하려고.
    - 또는 B보드에 합치기 전, 순환 동작만 따로 시험/검증하는 용도.

(2) 타이머 로직을 B보드 순환과 "같은 방식"으로 맞춘 이유
    - B보드: circOn 분 ON / circOff 분 OFF 위상 반복.
    - UP200_pump.ino: onMin 분 ON / offMin 분 OFF 위상 반복(기본 5/25).
    - "전과 같이 타이머"라는 요구대로, 동작 규칙을 동일하게 유지.
      → 나중에 B보드로 합쳐도 동작이 똑같다.

(3) IO26(순환 채널)을 기본 핀으로 둔 이유
    - B보드의 순환 채널(CH2)과 같은 핀이라, 그대로 옮겨도 일관성 유지.
    - #define 으로 빼놨으니 다른 핀으로 바꾸기도 쉬움.

(4) 릴레이 극성(relayLowTrig)과 drive() XOR를 그대로 둔 이유
    - B보드와 동일하게 LOW=ON 기본. 반대로 동작하면 't' 명령/상수로 토글.
    - 220V여도 "릴레이 IN 제어"라는 점은 같으므로 같은 패턴을 재사용.

(5) 시작 OFF + 1초 자가테스트를 둔 이유
    - 220V를 다루므로 시작은 반드시 OFF에서 출발(안전).
    - 1초 ON 자가테스트로 릴레이·배선이 제대로 붙는지 즉시 확인.

(6) 시리얼 명령(on=/off=/1/0/a/t/s)을 넣은 이유
    - 분 단위 주기 변경, 강제 ON/OFF, 자동 복귀, 극성 반전, 상태 확인을
      재업로드 없이 현장에서 바로 조정하기 위함(튜닝·점검 편의).


[ 4. 요약 — 12V 버전과의 차이 한눈에 ]
----------------------------------------------------------------
  항목            | 12V 버전            | 220V 교체 버전
  ----------------|---------------------|----------------------------
  A보드 코드       | 그대로              | 그대로(동일)
  B보드 펌프2 로직 | 타이머(circOn/Off)  | 타이머(동일) — 코드 변경 거의 없음
  펌프2 부하       | 12V DC 펌프         | 220V AC 펌프(UP200)
  펌프2 배선       | 12V 어댑터→릴레이    | 220V 활선 L 잘라 릴레이에 직렬
  추가 코드        | 없음                | UP200_pump.ino(독립 타이머)
  무게중심         | 코드                | 하드웨어·안전(코드는 거의 동일)

핵심: "릴레이는 부하 전압을 모른다"는 설계 덕분에,
      펌프를 220V로 바꿔도 제어 코드는 거의 그대로 재사용된다.
      바뀐 것은 주로 '배선'과 '안전 규칙'이다.
