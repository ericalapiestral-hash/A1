# v1.3.3 Aquarium BLE UUID 수정

실제 보드의 서비스 검색과 Android 캐시 갱신 후 재검색에서 다음 구성이 확인됐습니다. 기존 앱은 Nordic UART 형식의 `6e4000...` UUID만 사용해, BLE 연결이 된 뒤 서비스/특성 검사에서 실패했습니다.

| 역할 | 실제 Aquarium UUID | 확인된 속성 |
| --- | --- | --- |
| 서비스 | `4f7f1234-1234-5678-1234-aaaa00000001` | — |
| 상태 수신 | `4f7f1234-1234-5678-1234-aaaa00000002` | read, notify |
| 명령 전송 | `4f7f1234-1234-5678-1234-aaaa00000003` | write |

이 구성은 기존 AquaControl 구성과 명령/상태 UUID의 숫자 역할도 다릅니다. v1.3.3은 실제 Aquarium 구성을 별도로 추가하고, 알림은 `...02`, 명령은 `...03` 특성으로 처리합니다. 기존 AquaControl 구성도 계속 지원합니다.

상태 특성이 read를 지원하면 알림을 구독한 뒤 초기 상태를 한 번 읽습니다. read 실패로 정상 알림 연결을 해제하지 않습니다. JSON은 줄바꿈 없이 전송되거나 여러 패킷으로 나뉘어도 객체 경계 기준으로 조립하며, 문자열 속 괄호·이스케이프·UTF-8·여러 객체를 처리합니다. 잘못된 수신이 계속돼도 버퍼는 최대 8192바이트로 제한됩니다.

연결 진단에는 선택한 구성과 실제 명령/상태 UUID, 최초 수신 예시 최대 1024바이트가 포함됩니다. 진단은 앱 밖으로 자동 전송하지 않습니다. 실제 펌웨어의 센서 JSON 키와 명령 데이터 규격은 아직 확인되지 않아, 연결 후 센서값 또는 제어가 맞지 않으면 수신 예시와 펌웨어 규격을 확인해야 합니다. 앱은 기존 `key=value\n` 명령 형식을 사용합니다.

## 설치

버전은 `1.3.3+7`입니다. v1.3.1·v1.3.2와 같은 서명키를 사용하므로 이 버전들 위에 앱 삭제 없이 설치할 수 있습니다. 이전 v1.3.0은 다른 키로 서명돼 삭제 후 설치해야 합니다.

- [APK 다운로드](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/app/AquaControl-v1.3.3.apk)
- [ZIP 다운로드](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/app/AquaControl-v1.3.3.zip)

설치 후 설정 → 블루투스 → 다시 검색을 누릅니다. 진단에 `사용 구성: Aquarium`과 위의 명령/상태 UUID가 표시되는지, 센서값이 수신되는지 확인합니다. 연결 후 값이 갱신되지 않으면 연결 진단을 복사해 실제 수신 예시를 확인합니다.
