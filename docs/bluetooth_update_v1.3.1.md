# v1.3.1 블루투스 연결 수정

기존 앱은 BLE 이름이 `AquaControl`인 기기만 선택하여 `Aquarium`으로 표시되는 B보드를 무시했습니다. 새 버전은 두 이름을 모두 검색하며, 광고 이름과 휴대폰에 저장된 이름을 각각 확인합니다.

- 연결 후 수조 서비스와 명령/상태 특성을 확인하고 알림 구독이 완료되어야 연결됨으로 표시합니다.
- 권한 거부, 검색/연결 시간 초과, 호환되지 않는 펌웨어를 설정 화면에 표시합니다.
- 재검색 및 데모 전환 시 이전 검색과 연결 작업을 정리합니다.
- Android 12 이상은 근처 기기 권한, Android 11 이하는 위치 권한과 위치 기능을 안내합니다.
- 블루투스 명령 전송에 실패하면 제어값을 성공한 것처럼 변경하지 않습니다.

## 배포

업데이트 버전은 `1.3.1+5`입니다. 기존 배포 PC와 키 백업을 구할 수 없어 새 릴리스 키로 서명합니다. 기존 v1.3.0 앱 위에 덮어 설치할 수 없으며 **기존 앱 삭제 후 재설치**가 필요합니다. 앱의 로컬 데이터와 업데이트 다운로드 파일은 삭제됩니다.

```bash
flutter build apk --release
```

배포 승인을 받으면 `v1.3.1` 재설치용 사전 릴리스에 APK와 ZIP을 별도로 게시합니다. 기존 v1.3.0 앱의 자동 업데이트 조회는 안정 릴리스인 v1.3.0을 유지합니다.

새 서명키 백업 ZIP은 공개 저장소와 분리하여 보관합니다. 이후 같은 키를 사용하려면 백업의 `AquaControl-release.jks`와 `key.properties`를 `app/flutter_app/android/`에 복원합니다. 이후 버전부터 기존 `deploy.cmd`로 버전을 올려 같은 키의 업데이트를 배포할 수 있습니다.

기존 v1.3.0 APK 서명 인증서 SHA-256:

```text
acfb6105145511d0ed7400f2303b13c37f8fa8d6f4b43a43d337816d9f8bf400
```

이 인증서와 같은 키가 있어야 v1.3.0 위에 업데이트를 설치할 수 있습니다. 기존 PC의 `%USERPROFILE%\.android\debug.keystore`와 백업을 구할 수 없으므로 재설치 방식으로 전환합니다.

## 휴대폰 확인

Galaxy A34 5G / Android 16 / One UI 8.5에서 재설치 후 앱의 근처 기기 권한을 허용하고 설정 → 블루투스 → 다시 검색을 실행합니다. `Aquarium` 연결 후 센서값이 수신되는지 확인합니다. 수조 서비스가 없다는 안내가 나오면 해당 기기의 B보드 펌웨어와 BLE 서비스 UUID를 확인해야 합니다.

자동 테스트는 BLE 플랫폼을 모의하여 검색, 서비스 확인, 오류 전달, 알림 수신 및 검색 취소를 검증합니다. 실제 휴대폰과 B보드의 무선 연결은 별도 확인이 필요합니다.
