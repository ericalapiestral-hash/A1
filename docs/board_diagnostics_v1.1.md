# PC 보드 점검 프로그램 v1.1

기존 Aquarium A 펌웨어는 JSON 대신 다음 형식의 문자 로그를 출력합니다.

```text
pH=9.65(1.174V) | 탁도=3.118V | 수위낮음=1 | 급수=1 | 순환=1
```

v1.0에서는 원문을 수신해도 이 형식을 해석하지 못해 센서·출력 요약이 `미수신`으로 남았습니다. v1.1은 pH, 탁도 신호 전압, 수위 부족/정상, 급수·순환의 보드 보고 상태를 표시합니다. `수위낮음=1`은 부족, `0`은 정상으로 해석합니다. 이 상태 줄에 없는 히터·조도·GPIO는 추정하지 않습니다.

탁도 전압은 `V`로 표시하며 NTU로 환산하지 않습니다. 단위가 없는 JSON 수치는 단위 미확인으로 표시합니다. 저장소 A의 문자 로그에 명시된 NTU·조도 %는 해당 단위를 사용합니다. 보드 보고 ON은 실제 펌프 회전이나 히터 가열을 확인한 결과가 아닙니다.

문자 센서 상태 줄 수를 JSON 수와 별도로 표시합니다. JSON이 0개여도 문자 상태 줄이 수신됐다면 센서 값을 해석할 수 있습니다. 기존 TXT 보고서를 열면 보고서 머리말에 있는 요약 JSON을 제외하고 시리얼 원문만 다시 분석합니다. 수온 표시를 사용하지 않는다는 사실과 실제 보드 펌웨어에서 수온 센서가 제거됐는지는 구분해 표시합니다.

## 다운로드와 사용

[프로그램 ZIP](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/tools/board_diagnostics/AquaControl-Board-Diagnostics-v1.1.zip)을 풀고 `AquaControl-Board-Diagnostics.html`을 Edge 또는 Chrome에서 엽니다. 기존 보고서는 **기존 로그 파일 열기**로 재분석할 수 있습니다. Android 앱은 v1.3.6을 계속 사용합니다.

제어 전달을 확인할 때는 A와 B를 모두 켜고 B의 USB 포트에 115200 baud로 연결합니다. 휴대폰 앱을 Aquarium에 연결한 뒤 급수 **끄기**를 한 번 누르고 10초 정도 기다린 다음 B 보고서를 저장합니다. 두 보드를 동시에 기록하려면 브라우저 탭을 두 개 열어 서로 다른 포트를 선택합니다. 기록 중 USB를 바꿔 꽂으면 전원이 끊기거나 보드가 재부팅될 수 있습니다.

`[BLE] advertising 'Aquarium'`은 광고 시작이며 휴대폰 연결·명령 수신 완료를 뜻하지 않습니다. `[ESP-NOW] 수신 대기`도 센서 패킷 수신 성공이 아닙니다. `[REFILL] 시작`만으로 현재 펌프 출력·명령 규격·제어 주체를 확정하지 않습니다. 현재 실기 Aquarium 펌웨어는 저장소 A/B 소스와 다른 로그를 출력하므로 이 도구는 펌웨어를 덮어쓰거나 명령을 추측해 전송하지 않습니다.

## 검증

- Node 파서 테스트 10개: 분할 UTF-8/JSON, 잘린 프레임 복구, 문자 상태 수신과 변경, 누락값·잘못된 값 미추정, 보고서 머리말 제외, 단위 전환, 포트 재연결.
- Linux Chromium의 secure localhost와 모의 Web Serial: 연결/종료, JSON·문자 상태 표시, 단위 표시, 보고서 저장·재불러오기, 새 포트에서 이전 값 제거. 쓰기 스트림 접근 시 오류를 내는 모의 포트로 읽기 전용을 확인했습니다.
- 사용자 제공 Windows Chrome 보고서 2개를 로컬 재분석: A 문자 상태 24줄, B 부팅 메시지와 광고 시작. 사용자 원문 로그·장치 식별자는 저장소에 포함하지 않았습니다.

이 변경은 PC 점검 프로그램에 적용됩니다. APK 재빌드나 실제 보드 펌웨어 업로드, 실제 릴레이 출력 검증은 수행하지 않았습니다.
