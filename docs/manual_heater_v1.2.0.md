# Aquarium B v1.2.0 — 수동 히터와 GPIO18 연결 점검

기존 앱 v1.3.8에는 수동 히터 버튼이 있지만 B v1.0.1/v1.1.0에서는 히터 명령을 처리하지 않았습니다. 새 B는 `heaterMode=0/1`을 처리하고 `heaterMode`, `heaterOn`, `pin18`, `heaterManualSupported`를 회신합니다. 급수 수동·순환 수동/자동과 센서·LCD는 유지하며 **새 APK는 필요하지 않습니다**.

## 확인된 사실과 미확인 배선

- 원본 B의 히터 상태 토글은 명령 콜백 `0x400d2ea0` 부근에서 확인했습니다. 출력 루프 `0x400d3b29`~`0x400d3b37`은 히터 논리 상태를 반전해 GPIO18에 씁니다. 원래 소프트웨어는 HIGH를 논리 OFF로 취급했습니다.
- 현재 Aquarium 소스도 히터 핀이 GPIO18이며, v1.0.1/v1.1.0은 이 핀을 HIGH로 유지하고 히터 제어를 비활성화했습니다.
- 별도 저장소 `B_board/B_board.ino`는 히터 GPIO27을 쓰는 다른 설계입니다. 현재 Aquarium에서는 GPIO27이 LCD D4입니다. 예전 표와 현재 배선을 혼용하지 않습니다.
- 사용자는 실물 IN/COM/NO/NC 연결을 확인하지 못했습니다. 코드로 역할을 확인한 것이며 **실제 히터가 B GPIO18에 연결돼 있다고 확정하지 않습니다**. 원래 논리 OFF도 실물의 전력 차단을 증명하지는 않습니다.

## 다운로드와 처음 설치

[업데이트·릴레이 점검 ZIP](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/tools/heater_update/Aquarium-B-Heater-Update-v1.2.0.zip)

1. 히터·급수·순환 등 **모든 부하의 전원 플러그를 뽑고** B와 제어측만 USB로 연결합니다. 기존 로그/백업 도구에서 시리얼 연결을 종료합니다.
2. ZIP의 `Aquarium-B-Heater-Update.html`을 Windows Edge/Chrome에서 엽니다. 급수는 **현재 B 설정 자동 유지**, 히터는 기본 **잠금 유지**로 둡니다.
3. 앞서 저장한 원본 4MB B BIN을 선택하고 준비 확인 후 COM5를 선택합니다. 앱 영역만 쓰고 MD5를 검증합니다.
4. 완료 후 업데이트 도구의 연결이 닫히면 ZIP의 `Heater-Relay-Check.html`을 엽니다. B COM5에 연결하고 잠금 v1.2.0 상태를 수신할 때까지 기다립니다.
5. 부하 전원 분리 확인 후 GPIO18 LOW/HIGH를 눌러 어느 릴레이의 표시·작동 소리가 바뀌는지 관찰합니다. 각 점검은 최대 5초이며 이후 기존 HIGH로 돌아갑니다. 중지 버튼도 있습니다. **HIGH 복귀는 실제 히터 OFF 확인이 아닙니다.**
6. 관찰 결과를 적고 보고서 TXT를 저장합니다. GPIO18에 반응하는 릴레이가 실제 히터에 연결됐는지와 COM/NO/NC·정지 신호는 전원을 분리한 실제 배선 확인이 필요합니다. LED/작동 소리만으로 접점과 히터 정지를 단정하지 않습니다. AC 회로 확인은 적절한 작업자가 수행합니다.

## 배선 확인 뒤 활성화

점검 도구 연결을 종료하고 업데이트 HTML에서 확인된 히터 정지 신호 HIGH 또는 LOW를 선택합니다. **GPIO18 연결과 접점·정지 신호 확인란**을 선택해야 활성화 설치가 가능합니다. 같은 원본 BIN으로 다시 설치하며 현재 급수 설정을 보존합니다. 기존 앱 v1.3.8을 Aquarium에 연결하면 수동 끄기·켜기를 사용합니다.

확인할 상태는 `firmware: Aquarium-control-1.2.0`, `heaterManualSupported: true`, 부팅 `heaterMode: 0`, `heaterOn: false`, 실제 선택에 맞는 `pin18`입니다. 앱 ON은 계산한 출력 상태이며 전류나 가열 측정값은 아닙니다. 제품의 침수 조건, 자체 온도조절·과열보호와 전력 회로 정격은 별도로 확인해야 합니다.

배선을 모르면 잠금을 유지합니다. 잠금 상태의 `heaterMode/heaterOn`은 null이며 앱 명령을 거부합니다. 앱의 기존 히터 카드가 비활성 형태로 바뀌는 것은 아니므로, 잠금 상태에서 버튼을 누르면 적용 확인이 되지 않습니다. LCD에는 LOCKED가 표시됩니다.

## 제어와 점검 규칙

- 수온 센서·목표 온도·자동 온도 제어는 없습니다. `heaterMode=2`, 예전 토글 `H`, 온도 설정은 거부합니다.
- 설정된 히터는 부팅 OFF입니다. B가 BLE 연결 끊김을 감지하거나 E1을 처리하면 히터 ON 요청을 지웁니다. 재연결/E0 해제만으로 다시 켜지지 않습니다. 전원·접점 고장이나 실제 온도를 감시하는 하드웨어 보호를 대신하지는 않습니다.
- BLE가 끊긴 동안 앱에는 마지막 수신값이 남을 수 있습니다. 재연결 후 `heaterMode=0`과 `heaterOn=false`를 확인합니다. 끊김을 B가 감지하는 데 걸리는 시간이나 실제 접점 차단 시간을 보장하지 않습니다.
- 급수와 순환의 기존 수동 상태 유지 정책은 바꾸지 않습니다.
- USB 점검은 **히터 잠금 상태에서만** `check18=0/1/stop`을 받습니다. BLE 점검 명령, 활성화된 히터의 USB 점검, 비상정지 상태의 점검은 거부합니다. USB로 일반 펌프/히터 ON 명령을 실행하지 않습니다.
- 점검 화면은 정확한 v1.2.0 잠금 상태와 최근 상태 수신, 부하 전원 분리 확인이 있어야 LOW/HIGH를 보낼 수 있습니다. 상태가 오래되거나 수신이 종료되면 차단합니다. 관찰 보고서는 GPIO 보고와 사용자 관찰을 담으며 물리 연결/가열을 자동 판정하지 않습니다.
- `PeerConfig` 40바이트 중 기존 A 필터 6바이트·급수 설정 1바이트를 유지하고 남은 1바이트를 히터 극성에 사용합니다. 미설정은 GPIO18의 기존 HIGH를 유지합니다. 선택된 OFF 래치를 설정한 다음 출력 핀을 활성화하고 수준을 다시 적용합니다.

## 업데이트와 복원

원본, 순환 v1.0.1, 급수 v1.1.0의 설정별 이미지, 새 v1.2.0 설정 조합을 검증합니다. 기본 급수 자동 유지는 연결 B에서 일치한 이미지의 급수 설정을 읽어 보존합니다. 중단 뒤에는 검증해 저장한 같은 B의 설정만 재사용합니다. 설정을 알 수 없는 중단 대상은 임의로 추측하지 않습니다.

급수·순환 v1.1.0(급수 설정 유지), 순환 전용 v1.0.1, 더 이전 원본 앱으로 복원할 수 있습니다. 복원 전에도 히터를 포함해 모든 부하 전원을 분리합니다. 이전 프로그램은 히터 동작 정책이 다르며 원본에는 토글 기능이 있었습니다.

앱 `0x10000`만 쓰고 전체 삭제·다른 주소 쓰기를 차단합니다. A·부트로더·파티션·NVS·SPIFFS는 보존합니다. 원본 BIN/NVS/MAC은 공개 배포에 포함하지 않고 개인화는 브라우저 안에서 수행합니다. 실제 장치 식별 해시는 같은 대상 복원을 위해 해당 브라우저에 저장합니다.
