# v1.3.4 Aquarium 상태 수신 및 수위 표시 수정

v1.3.3 현장 진단에서는 Aquarium UUID 구성이 정상 선택되고 상태값도 수신됐습니다. 그러나 앞의 두 알림이 각각 20바이트에서 잘린 뒤 완전한 JSON이 이어지면서, 앱의 JSON 조립기가 객체 종료를 기다린 채 유효한 상태를 전달하지 못했습니다. 기존 화면은 수위 기본값 `level=1`을 계속 `정상`으로 표시했습니다.

보드가 실제 보낸 키는 `water_low:1`입니다. 앱은 기존 `level` 키만 읽어 수위 부족 상태를 반영하지 못했고, 온도·조도·설정값도 제공되지 않았는데 이전 값이나 데모 기본값을 표시했습니다. 이 진단으로 모든 센서 하드웨어의 정상 동작을 보장할 수는 없지만, 앱의 상태 해석·표시 문제는 재현됐습니다.

## 수정

- Aquarium 구성에서 서비스 확인 후, 알림 활성화 전에 Android MTU 512를 요청합니다. 최대 5초로 제한하며 실패 시 오류를 기록하고 초기 read 및 알림 설정을 계속 시도합니다. 실제 협상 결과는 진단에 표시합니다.
- 초기 상태 read를 알림 구독 전에 수행해 두 수신 경로의 패킷이 같은 조립 버퍼에 섞이지 않게 합니다.
- 실제 잘린 JSON 뒤의 새 객체 시작을 감지해 불완전한 메시지를 버리고 정상 프레임으로 복구합니다. 기존 JSON의 중첩 객체·문자열·이스케이프·UTF-8 처리는 유지합니다.
- `water_low:1`은 수위 `부족`, `water_low:0`은 `정상`으로 표시합니다. 상태 별칭 `sup`, `cir`, `ht`는 급수·순환·히터의 0/1 보고 상태로 읽습니다. 보고 상태만으로 실제 하드웨어 동작을 검증했다고 판단하지 않습니다.
- `ph`, `turb` 수신값을 반영하고 Aquarium의 탁도 값은 소수점 두 자리로 표시합니다. 이 펌웨어의 탁도 단위가 확인되지 않아 Aquarium에는 NTU 단위를 붙이지 않습니다.
- 수온·조도·목표 수온·모드·주기 설정 등 보드에서 안 보내는 항목은 `미수신` 또는 `--`로 표시합니다. 수온이 없으면 추이 그래프에 데모 값을 추가하지 않습니다.
- `con`, `cof`, `son`, `sof`, `smode`의 단위/규칙은 확인되지 않아 기존 앱의 분 단위 타이머·모드 값으로 추측해서 변환하지 않습니다. 실제 제어 명령 규격도 확인되지 않았으며 기존 `key=value\n` 형식을 변경하지 않습니다. UI는 보드가 확인해 주지 않은 모드를 선택된 상태로 표시하지 않습니다.
- 연결 진단에 초기 read/notify 구분, 패킷 길이, 완전한 JSON 수, 폐기한 메시지 수, 마지막 완전한 JSON을 추가합니다. 원문 수신 예시는 최대 1024바이트이며 앱 밖으로 자동 전송하지 않습니다.

## 설치와 확인

버전은 `1.3.4+8`입니다. v1.3.1·v1.3.2·v1.3.3과 같은 키로 서명하므로 앱을 삭제하지 않고 설치할 수 있습니다. 이전 v1.3.0은 다른 서명키로 만들어져 삭제 후 설치가 필요하며 로컬 앱 데이터가 삭제됩니다.

- [APK 다운로드](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/app/AquaControl-v1.3.4.apk)
- [ZIP 다운로드](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/app/AquaControl-v1.3.4.zip)

설정 → 블루투스 → 다시 검색으로 연결합니다. 진단의 `완전한 JSON` 수가 증가하고, `마지막 완전한 JSON`의 `water_low:1`에 대해 화면이 `부족`으로 표시되는지 확인합니다. 초기 read 한 번 성공한 것만으로 지속적인 notify 수신까지 정상이라고 판단하지 않습니다. 히터·펌프 제어는 실제 펌웨어 명령 규격과 출력 동작을 별도로 확인해야 합니다.

## 검증

테스트 24개 및 변경 파일 분석이 통과했습니다. 실제 수신 로그를 넣어 v1.3.3에서 pH가 기본값 7.1에 머무는 실패를 재현한 뒤, 수정 후 pH 9.70·탁도 3.12·수위 부족 반영을 확인했습니다. MTU 협상 순서와 실패 시 연결 유지, 기존 AquaControl 상태 호환성, 미수신 센서·설정에 데모 값을 표시하지 않는 화면도 검증했습니다. Android의 실제 MTU 협상 결과와 Galaxy A34/B보드의 지속적인 수신·센서 하드웨어·히터 출력은 현장 확인이 필요합니다.
