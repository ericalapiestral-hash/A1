AquaControl — 코드를 몰라도 설명할 수 있는 발표용 문장
기준: 2026-10-15 / 앱 v1.3.8 / Aquarium B v1.1.0

이 파일은 PPT 파일이 아니라 발표할 때 읽거나 본인 PPT에 옮겨 적을 수 있는 문장 모음입니다.
그림은 images 폴더의 PNG를 사용하면 됩니다. 모든 그림은 코드 기준 설명도이며 실물 사진이 아닙니다.
설치·실기 확인 범위는 01_상세설명_센서_전기_배선_코드.txt를 함께 참고하세요.

============================================================
1. 30초 소개
============================================================

“이 장치는 수조 상태를 스마트폰에서 확인하고 펌프를 제어하는 시스템입니다.
ESP32 A보드는 센서값을 측정하고, B보드는 그 값을 받아 LCD와 앱에 보여줍니다.
사용자가 앱에서 버튼을 누르면 B보드가 릴레이를 통해 펌프 전원을 제어합니다.
급수는 원할 때 켜고 끄는 수동 방식이며, 순환은 수동과 시간 반복 자동 방식을 제공합니다.”

============================================================
2. 그림별 설명 — 한 장당 약 20~40초
============================================================

[그림 01: 전체 구성]
파일: images/01_system_overview.png

“이 그림은 정보와 명령이 어디로 이동하는지를 보여줍니다.
센서값은 A보드에서 B보드로 ESP-NOW라는 무선 방식으로 전달됩니다.
B보드와 스마트폰은 BLE 블루투스를 사용합니다.
스마트폰이 센서를 직접 읽거나 펌프에 전원을 직접 공급하는 것은 아니고,
B보드가 그 중간에서 정보를 전달하고 펌프 제어를 처리합니다.”

그림에 붙일 짧은 문구:
  A는 측정, B는 통신·제어, 앱은 확인·조작을 담당한다.

[그림 02: 센서 연결]
파일: images/02_current_sensors.png

“현재 통신에서 확인된 센서 정보는 pH, 탁도 전압, 수위 부족 여부입니다.
pH는 산성·알칼리성을 판단하는 데 쓰고, 탁도 센서는 물의 흐림에 따른 신호를 만듭니다.
수위 센서는 설치된 지점의 물 감지 상태를 알려줍니다.
다만 센서 숫자가 들어온 것과 실제 측정이 정확하다는 것은 별도이므로 보정이 필요합니다.
A보드 원본 소스가 없어 정확한 입력 핀은 확인 필요로 표시했습니다.”

그림에 붙일 짧은 문구:
  센서 수신은 확인됐지만 실제 핀·모델·정확도는 구분해서 검증한다.

[그림 03: B보드 핀 연결]
파일: images/03_b_board_connections.png

“현재 Aquarium B 코드에서 급수는 GPIO16, 순환은 GPIO17을 사용합니다.
이 핀은 펌프의 전원선이 아니라 릴레이에 신호를 주는 선입니다.
LCD에는 13, 14, 27, 26, 25, 33번을 사용합니다.
예전 저장소 B 코드에서는 펌프 핀이 25, 26으로 다르므로,
어느 버전의 배선표인지 확인하는 것이 중요합니다.”

그림에 붙일 짧은 문구:
  현재 B 코드의 핀 배치와 예전 B 설계의 핀 배치를 혼용하지 않는다.

[그림 04: LCD 연결]
파일: images/04_lcd_wiring.png

“LCD는 스마트폰 없이도 현장에서 상태를 확인하기 위해 사용합니다.
RS와 E 두 선은 내용을 어떻게 받아들일지 정하고,
D4부터 D7까지 네 선은 글자 데이터를 전달합니다.
네 개 데이터선을 나누어 쓰는 4비트 방식으로 핀 사용을 줄였습니다.
작은 화면이라 여러 정보를 한꺼번에 표시하지 않고 약 3초마다 페이지를 바꿉니다.”

그림에 붙일 짧은 문구:
  병렬 4비트 LCD로 센서·급수·순환·연결 상태를 순서대로 표시한다.

[그림 05: 릴레이와 펌프]
파일: images/05_relay_and_dc_pump.png

“ESP32는 작은 제어 신호를 만들고, 릴레이가 펌프 전원 회로를 열거나 닫습니다.
릴레이는 전기를 만들어 주는 장치가 아니라 스위치 역할입니다.
COM은 공통 접점, NO는 코일이 쉬는 상태에서 열리는 접점입니다.
이 그림은 DC 펌프에 NO 접점을 사용하는 원리 예시이며,
현재 실물에서 어떤 접점을 쓰는지는 따로 확인해야 합니다.”

그림에 붙일 짧은 문구:
  제어 신호와 펌프 전력은 역할이 다르며 릴레이 접점으로 스위칭한다.

[그림 06: 전원 구역]
파일: images/06_power_domains.png

“보드와 센서가 쓰는 전원과 펌프가 쓰는 전원은 정격을 따로 확인합니다.
USB는 5V지만 ESP32의 신호는 일반적으로 3.3V 수준입니다.
센서가 5V로 작동하더라도 그 출력이 ESP32 입력에 안전한지는 별도 확인이 필요합니다.
펌프가 DC인지 AC인지도 제품 명판을 봐야 하며,
고전압 전력선과 작은 신호선은 구분해야 합니다.”

그림에 붙일 짧은 문구:
  전원 전압, 신호 전압, 펌프 전류를 각각 확인한다.

[그림 07: 센서 측정 원리]
파일: images/07_sensor_signal_principles.png

“센서는 물의 상태를 전압이나 0과 1의 신호로 바꿉니다.
보드는 ADC라는 기능으로 전압을 숫자로 읽습니다.
전압이 너무 높으면 분압이나 레벨 변환이 필요하고,
값이 흔들리면 평균이나 필터를 이용해 완화합니다.
현재 탁도는 NTU가 아니라 전압 V로 들어오므로 단위를 정확하게 설명해야 합니다.”

그림에 붙일 짧은 문구:
  센서 신호 조정 → 숫자 읽기 → 보정·해석 → 사용자 표시.

[그림 08: 제어 순서]
파일: images/08_control_and_timing.png

“앱에서 버튼을 누르면 명령이 BLE로 전달되고, B보드는 그 뜻을 해석해 출력을 바꿉니다.
이후 어떤 모드가 적용됐는지 앱에 다시 알려줍니다.
급수는 수동 켜기·끄기만 있으며 수위가 바뀌어도 자동으로 작동하지 않습니다.
순환은 자동을 선택하면 기본 120초 작동, 60초 휴식을 반복합니다.
앱의 보드 ON은 출력 보고값이므로 실제 펌프 회전은 별도로 확인합니다.”

그림에 붙일 짧은 문구:
  명령 전송, 보드 적용 확인, 실제 펌프 작동 확인은 서로 다른 단계다.

============================================================
3. 코드 설명을 시작할 때 쓸 문장
============================================================

“코드는 크게 시작할 때 준비하는 부분과 계속 반복해서 일하는 부분으로 나뉩니다.
setup은 핀과 통신을 준비하고, loop는 명령을 처리하고 출력을 바꾸며 상태를 보냅니다.
급수 규칙은 ManualSupply.h, 순환 규칙은 Circulation.h에 따로 정리했습니다.
그래서 급수의 자동 기능을 제거하면서 순환의 자동 기능은 유지할 수 있었습니다.”

“앱 쪽은 통신 담당, 상태 기록 담당, 화면 담당으로 나뉩니다.
ble_manager는 연결과 데이터 전송, aqua_api는 명령과 확인 과정,
models는 상태 저장, control_tab은 사용자가 누르는 제어 화면을 맡습니다.”

“가장 중요한 수정은 명령이 도착한 것만 보고 성공이라고 생각하지 않도록 한 것입니다.
B가 그 명령을 해석하고 같은 설정값을 돌려줬을 때 앱이 적용 확인으로 표시하도록 했습니다.”

============================================================
4. 예상 질문과 쉬운 답변
============================================================

Q. 왜 보드를 두 개 사용했나요?
A. 센서 측정과 펌프 제어 역할을 나누기 위해서입니다. 두 보드 사이에는 무선으로 값을 전달합니다.
   측정부와 제어부를 따로 배치하고 문제 원인을 나누어 확인하기 좋습니다.

Q. 인터넷이 없어도 되나요?
A. 센서 전달은 ESP-NOW, 앱 제어는 BLE이므로 기본 측정·제어 경로에 인터넷 공유기가 필수는 아닙니다.
   앱이나 업데이트 파일을 내려받는 과정에는 인터넷이 필요할 수 있습니다.

Q. 왜 릴레이를 사용하나요?
A. ESP32 핀에서 펌프에 필요한 전력을 직접 공급할 수 없기 때문입니다.
   ESP32는 제어 신호만 주고, 릴레이 접점이 별도 펌프 전원 회로를 열거나 닫습니다.

Q. HIGH면 항상 펌프가 켜지나요?
A. 아닙니다. 릴레이 입력 극성과 NO/NC 접점에 따라 달라집니다.
   현재 순환은 실기 결과에 맞춰 HIGH를 작동, LOW를 정지로 맞췄고 급수는 설치 때 확인해 선택합니다.

Q. 수위가 낮아지면 급수가 켜지나요?
A. 현재 새 버전은 그렇게 동작하지 않습니다. 급수 자동을 제거했으므로 사용자가 켜고 끕니다.
   물이 차도 자동 정지하지 않으므로 급수 중에는 상태를 확인해야 합니다.

Q. 순환 자동의 기본 시간은 무엇인가요?
A. AUTO를 선택하면 2분 작동, 1분 휴식을 반복합니다. 앱에서 시간을 변경할 수 있습니다.
   전원을 켰을 때 기본 모드는 OFF이며 바로 AUTO를 시작하지 않습니다.

Q. 블루투스 연결이 끊어지면 펌프가 꺼지나요?
A. 현재 수동 급수와 수동 순환은 마지막 모드를 유지합니다. 연결 끊김만으로 자동 정지하지 않습니다.
   B가 재부팅되면 기본 OFF로 시작합니다. 전원 단절 때의 실제 접점 동작은 배선에 따라 별도 확인해야 합니다.

Q. 앱에서 ON이면 펌프가 확실히 돌고 있나요?
A. 앱은 B가 계산해서 보낸 출력 상태를 보여줍니다. 실제 회전이나 유량을 읽는 센서는 구현돼 있지 않습니다.
   실제 물 이동은 현장에서 따로 확인해야 합니다.

Q. pH 값이 들어오면 정확한 측정인가요?
A. 숫자를 수신한 것과 측정 정확도는 다릅니다. pH 기준 용액 등으로 보정과 비교 검증이 필요합니다.

Q. 탁도 3.12는 무엇인가요?
A. 현재 Aquarium 통신에서는 전압 3.12V를 뜻합니다. 보정된 탁도 단위인 NTU라고 말하면 안 됩니다.

Q. 수온과 조도도 측정하나요?
A. 수온 센서는 제거한 구성입니다. 현재 Aquarium 센서 묶음에는 조도도 없습니다.
   저장소에 조도 코드가 남아 있는 것과 현재 장비가 그 값을 보내는 것은 다른 이야기입니다.

Q. 왜 처음에는 연결됐는데 제어가 안 됐나요?
A. 연결 주소가 맞는 것과 명령 규칙이 맞는 것은 별개입니다.
   원래 B는 앱의 pump2Mode 명령을 로그에 출력했지만 실제로 처리하지 않았습니다.
   새 코드에서 모드 명령을 처리하고 적용 상태를 돌려주도록 바꿨습니다.

Q. 왜 원본 BIN을 백업했나요?
A. 소스가 없는 B의 기능과 통신 규칙을 분석하고, 문제가 생기면 원본 프로그램으로 돌아가기 위해서입니다.
   BIN을 확보했다고 원래 Arduino 소스가 그대로 복원된 것은 아닙니다.

Q. 지금 모든 것이 실물에서 검증됐나요?
A. 순환 제어는 사용자의 실기 확인을 받았습니다. 급수 새 버전은 코드·앱·모의 설치 검증과 배포를 마쳤습니다.
   실제 급수 배선·극성·작동과 센서 보정은 추가 확인 대상입니다.

5. 발표 마무리 예시
============================================================

“이 프로젝트에서 중요했던 것은 센서값을 읽는 기능만이 아니라,
앱이 보낸 명령이 보드에서 실제로 적용되는지 확인하는 과정이었습니다.
역할을 측정·통신·제어로 나누고, 각 단계의 상태를 보여주도록 구성했습니다.
순환 제어는 실물에서 확인했으며 급수는 수동 제어 버전으로 확장했습니다.
앞으로는 실제 급수 동작과 센서 보정, 정확한 실물 배선 정보를 추가 검증할 수 있습니다.”

발표에서 피할 표현:
  '전부 완벽하게 작동한다' → 확인된 기능과 남은 확인을 구분한다.
  '센서값은 정확하다' → 수신 확인과 보정 검증을 구분한다.
  '물이 차면 급수가 자동 정지한다' → 현재는 수동 급수이다.
  '이 그림은 실제 사진이다' → 코드와 확인된 사실에 근거한 설명도이다.
  '현재 A 핀은 32/34/35다' → 그 번호는 별도 저장소 A 코드의 참고값이다.
