# 릴레이 점검 도구 v1.2.1 — USB 상태 무수신 대응

사용자가 COM 연결은 되지만 ‘B 펌웨어 상태 수신 대기’에서 멈추고 원문 로그가 완전히 비어 있다고 보고했습니다. 기존 USB 로그 도구에는 있던 **연결 직후 DTR/RTS 해제**가 v1.2.0 릴레이 점검 화면에는 누락돼 있었습니다. 이 누락은 보드·드라이버·자동 리셋 회로에 따라 실행/수신을 막을 수 있습니다. 사용자 보드에서 직접 재현한 것은 아니므로 이것만이 확정 원인이라고 단정하지 않습니다.

후속 사용자 보고서에서는 EN을 누른 뒤 정상 SPI 플래시 부팅과 `Aquarium-control-1.2.0` 상태 수신, GPIO18 LOW/HIGH 점검 처리 및 5초 복귀가 확인됐습니다. 사용자는 LOW 때 4채널 모듈의 IN3 표시가 켜지고 복귀 후 꺼졌다고 관찰했습니다. GPIO18→IN3 제어 경로는 확인됐지만 실제 히터의 IN3 접점 연결과 NO/NC는 미확인입니다. 새 v1.2.1의 DTR/RTS 변경만으로 해당 보드의 무수신이 재발하지 않는지는 아직 확인되지 않았습니다. 사용자 원문 보고서는 공개 배포에 포함하지 않습니다.

## 다운로드와 사용

- [점검 화면만 수정한 ZIP](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/tools/heater_update/Heater-Relay-Check-v1.2.1.zip) — 7,424바이트, HTML과 안내 TXT 2개
- [전체 업데이트 도구 묶음](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/tools/heater_update/Aquarium-B-Heater-Update-v1.2.1.zip) — 2,762,569바이트

**B 펌웨어는 v1.2.0 그대로입니다. 이미 설치했다면 다시 업로드하지 않습니다.** 전체 묶음의 업데이트 HTML도 이전 v1.2.0과 바이트 단위로 같습니다.

1. 히터·급수·순환 등 모든 부하 전원 플러그를 뽑고 B와 제어측만 USB 전원을 연결합니다. USB 신호 변경/정상 재시작으로 제어 상태가 초기화될 수 있습니다.
2. 기존 점검 화면에서 연결 종료 후 창을 닫고, 새 ZIP을 풀어 `Heater-Relay-Check.html`을 Edge/Chrome에서 엽니다. 제목에 v1.2.1이 있는지 확인합니다.
3. 현재 B의 COM을 선택합니다. 연결 직후 DTR/RTS를 해제하고 읽기 전용 `status`를 요청합니다. 수신 바이트와 펌웨어 상태를 확인합니다.
4. 8초 이상 0바이트이면 부하 전원 분리 확인 후 **B 정상 재시작 · 펌웨어 유지**를 한 번 누릅니다. 지원되지 않으면 B의 EN/RST를 한 번 누르고 BOOT는 누르지 않습니다.
5. 계속 안 되면 새 보고서 TXT를 저장합니다. 수신 바이트, 상태 수, 리셋 신호 해제 결과, 다운로드 모드 감지, 명령, 원문 잔여 로그가 포함됩니다.

이전 형식 JSON이나 다른 펌웨어가 수신되면 잘못된 COM 또는 히터 잠금 v1.2.0 설치 여부를 확인합니다. 실제 히터 배선과 정지 신호는 [기존 설치 안내](manual_heater_v1.2.0.md)의 확인 절차를 따릅니다.

## 변경 내용

- 115200/8N1/흐름제어 없음으로 열고 `setSignals({dataTerminalReady:false,requestToSend:false})`를 적용합니다.
- 연결 후 0.3/1.5/4초에 `status`만 요청합니다. 자동 GPIO18 점검·정상 재시작·플래시 쓰기는 하지 않습니다.
- 수신 바이트/상태 수와 8초 무수신 안내를 표시합니다. `DOWNLOAD_BOOT`/`waiting for download`를 표시하고 점검을 차단합니다.
- 정상 재시작은 사용자가 부하 전원 분리를 확인하고 누른 경우만 BOOT 해제/DTR false 상태에서 RTS true→120ms→false로 요청합니다. 실패하면 물리 EN/RST 사용을 안내합니다. 펌웨어를 기록하거나 지우지 않습니다.
- 로그 접두사·BOM·조각·줄바꿈 없는 완성 JSON과 시작 시 불완전 평면 상태 프레임에 대응합니다. 부분 원문도 보고서에 보존합니다.
- 정확한 잠금 펌웨어·필드·최근 상태·전원 확인·비상정지 조건을 유지하고, 다운로드 모드·수신 종료·오래된 상태에서 LOW/HIGH를 차단합니다.
- GPIO18 점검은 명시적 버튼 입력으로만 수행하며 펌웨어의 5초 제한은 그대로입니다.

## 검증 범위

실제 배포 HTML과 모의 Web Serial로 리셋 해제 전 무수신→해제 후 status 응답, 비동기 조각/접두사/줄바꿈 없는 JSON, 다운로드 모드 차단과 수동 정상 재시작, 0바이트 안내, 자동 재시작/릴레이 명령 없음, 전원/펌웨어/최근 상태 차단, 보고서와 연결 종료를 검증했습니다. 기존 모의 설치·설정 유지·복원 시나리오도 통과했습니다.

독립 ZIP은 HTML/TXT 2개이며 전체 묶음의 업데이트 HTML/펌웨어가 기존 v1.2.0과 동일함을 대조했습니다. B/앱 코드를 변경하지 않았으므로 펌웨어 재컴파일·앱 재설치는 하지 않았습니다. 실제 Windows USB/보드에서 수신이 복구되는지는 현장 확인이 필요합니다.
