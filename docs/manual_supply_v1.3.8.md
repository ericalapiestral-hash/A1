# 급수 수동 제어 — 앱 v1.3.8 / Aquarium B v1.1.0

현재 순환 v1.0.1은 사용자가 실제 펌프의 끄기·켜기와 앱 제어가 정상 작동하는 것을 확인했습니다. 급수를 다시 사용하기 위해 앱의 급수 자동 선택과 데모 수위 자동 작동을 제거하고 B에 `pump1Mode=0/1` 수동 명령을 추가합니다. 순환의 OFF/ON/AUTO와 주기 설정은 유지합니다.

## 동작

- 급수는 수동 끄기·켜기만 있습니다. `pump1Mode=2`, 기존 자동 급수 모드·주기 명령은 거부하며 상태를 바꾸지 않습니다.
- 급수는 수위·순환 타이머와 무관하게 선택 상태를 유지합니다. 켜기를 누르면 사용자가 끌 때까지 유지되며 BLE·A 센서 통신 단절로 자동 정지하지 않습니다. B 재부팅 시 기본은 끄기입니다.
- 앱은 B에서 `manualSupplySupported: true`를 받은 경우 급수 버튼을 활성화합니다. 이전 순환 전용 B나 출력 미설정 B에는 업데이트/출력 설정 안내를 표시합니다.
- BLE 쓰기 성공만으로 적용됐다고 표시하지 않습니다. 새 상태 JSON의 `pump1Mode` 값이 요청과 일치하면 보드 설정 확인으로 표시합니다. `pump1On`은 보드가 계산한 출력 상태이며 실제 펌프 회전을 측정하지는 않습니다.
- 미설정 급수 출력은 `pump1Mode/pump1On: null`로 보고하며 앱도 미수신으로 표시합니다. 수온 센서와 히터 출력은 사용하지 않습니다.

## 배선과 설정

원래 B 백업에서 급수 GPIO16, 순환 GPIO17, 히터 GPIO18, 병렬 LCD RS13/E14/D4=27/D5=26/D6=25/D7=33을 확인했습니다. 사용자는 급수가 B에 연결됐다고 확인했으며 실제 급수 IN이 GPIO16인지와 신호 극성은 현장 확인이 필요합니다. 현재 순환 전용 v1.0.1은 GPIO16을 HIGH로 유지합니다.

급수 전원을 연결했을 때 앱 조작 없이 정지하는지 또는 작동하는지를 잠깐 확인하고 전원을 다시 끕니다. 물이 나올 수 있으므로 확인하는 동안 지켜봅니다. 설치 도구에서 그 결과를 선택합니다. 정지하면 HIGH=OFF, 작동하면 LOW=OFF로 설정합니다. 이를 확인하지 않은 기본 선택에서는 설치가 차단됩니다. 모르면 임의로 선택해 설치하지 말고 현재 상태를 알려주세요.

공개 템플릿은 A 송신 MAC과 급수 극성 설정이 비어 있습니다. 도구는 원본 백업의 A 송신 필터 6바이트와 선택한 설정 1바이트를 브라우저 안에서 복사하고 ESP 이미지 XOR 체크섬·SHA-256을 다시 계산합니다. 두 극성 모두 선택한 OFF 래치를 먼저 설정하고 GPIO16 출력을 활성화합니다. 미설정 템플릿은 기존 HIGH를 유지하며 급수 명령을 받지 않습니다. 히터 GPIO18은 기존 HIGH를 유지하므로 히터 부하 전원은 계속 분리합니다.

순환 GPIO17의 검증된 LOW=정지/HIGH=작동 설정과 기존 A의 12바이트 센서 패킷·송신 필터·BLE UUID를 유지합니다. A를 새로 업로드하지 않습니다. 보드나 릴레이 전원이 꺼져도 실제 펌프가 정지하는지는 NO/NC 접점·배선에 따라 다르므로 별도 확인이 필요합니다.

## 설치

1. [앱 v1.3.8 APK](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/app/AquaControl-v1.3.8.apk)를 기존 v1.3.7 위에 설치합니다. 서명이 같으므로 앱 삭제가 필요 없습니다. [APK ZIP](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/app/AquaControl-v1.3.8.zip)도 제공합니다.
2. 위 급수 상태를 확인한 뒤 급수·순환펌프·히터 전원을 끄고 기존 점검/백업 도구의 시리얼 연결을 종료합니다.
3. [B 업데이트 도구 ZIP](https://raw.githubusercontent.com/ericalapiestral-hash/A1/main/tools/aquarium_update/Aquarium-B-Pump-Update-v1.1.0.zip)을 풀어 `Aquarium-B-Pump-Update.html`을 Edge/Chrome에서 엽니다.
4. 급수의 기존 정지/작동 상태를 선택하고 앞서 저장한 **원본 4MB B BIN**을 선택합니다. 순환 v1.0.1을 다시 백업할 필요는 없습니다.
5. 기본 업데이트와 준비 확인을 선택한 뒤 B의 COM5를 선택합니다. 현재 앱·파티션·ESP32/4MB 구성과 보안 설정을 확인한 후 앱 영역 `0x10000`만 쓰고 MD5를 검증합니다.
6. 완료 후 앱을 Aquarium에 다시 연결합니다. 진단의 `firmware: Aquarium-pumps-1.1.0`, `manualSupplySupported`, `pump1Mode`, `pump1On`, `pin16`을 확인합니다. 펌프 전원을 다시 연결하고 급수 끄기·켜기를 각각 확인합니다. 수위 변화에 자동 반응하지 않는 것도 확인합니다. 히터 전원은 분리 상태를 유지합니다.

## 설치 오류와 복원

새 도구는 원본 Aquarium 앱, 개인화된 순환 v1.0.1, 새 수동 급수의 두 극성 이미지를 확인합니다. 따라서 브라우저에 이전 대상 기록이 없어도 정상 순환 v1.0.1에서 업그레이드할 수 있습니다. 다른 칩·용량·파티션·알 수 없는 펌웨어와 보안 부팅·암호화 설정은 거부합니다. 전체 삭제·다른 영역 쓰기를 막으며 부트로더·파티션·NVS·SPIFFS를 보존합니다.

설치 중 실패하면 보고서 TXT를 저장하고 같은 화면에서 **잘 작동했던 순환 v1.0.1로 복원**을 선택할 수 있습니다. 복원할 때는 급수·히터 전원을 분리합니다. 더 이전 원본 Aquarium 앱 복원도 있으나 기존 수동 순환 미지원 문제가 돌아옵니다. 쓰기 중단 뒤에는 브라우저에 저장한 대상 식별 해시로 같은 B만 복원하도록 제한합니다. 저장이 제한되면 화면을 닫기 전에 복원합니다. 급수 극성을 잘못 선택한 경우 실제 상태를 다시 확인해 올바른 선택으로 재설치할 수 있습니다.

원문 백업·NVS·MAC은 공개 저장소와 ZIP에 포함하지 않습니다. 사용자 파일과 로그는 서버로 전송하지 않습니다. 현재 앱 자동 업데이트가 확인하는 정식 릴리스는 이전 키를 사용하므로 이 APK와 도구는 링크에서 직접 받는 사전 릴리스로 제공합니다.

## 검증 범위

- Flutter 테스트 37개 통과. 급수 두 버튼·자동 요청 차단·지원 여부에 따른 활성화·BLE ACK와 적용 확인 구분·출력 null·수위가 데모 급수를 자동 시작하지 않는 경우를 포함합니다. 수정 Dart 파일 분석 문제 없음.
- APK v1.3.8+12 릴리스 빌드·패키지/버전·서명 검증 완료. 인증서 SHA-256은 v1.3.7과 동일합니다.
- ESP32 core 3.3.2, NimBLE-Arduino 2.5.1, LiquidCrystal 1.0.7, huge_app 컴파일 통과. 프로그램 1,144,855바이트, RAM 53,512바이트.
- C++ 급수·순환 테스트 통과: 두 극성의 부팅 OFF, 수동 상태 유지, 자동/잘못된 명령 거부, 타이머·센서에 의한 급수 변경 없음, 미설정 제어 차단, 순환 AUTO와 millis wrap, 비상정지 억제.
- 기계 코드에서 GPIO16 설정을 읽은 뒤 OFF 래치→출력 활성화→레벨 재적용 순서를 확인했습니다. 상태 JSON은 512바이트 제한 안에 들어갑니다.
- 업데이터 코어의 이미지 무결성·앱 영역 설치/복원·외부 보드 거부·중단 복원·극성 필수 선택·기존 v1.0.1 업그레이드·두 극성 수정·복구 이미지 무결성 10개 항목을 검증했습니다. 실제 배포 HTML과 제공된 백업 데이터를 사용한 Chromium 모의 검증에서 선택 전 설치 차단, 대상 기록 없는 v1.0.1 업그레이드, 두 극성 설치, 보고서 저장, v1.0.1 복원, 원본 복원, 외부 보드 거부를 확인했습니다.

실제 Windows USB 업로드와 급수펌프 시험은 이 작업 환경에서 수행하지 않았습니다. 급수의 실제 작동과 배선 확인은 설치 후 현장 단계입니다. E1 비상정지는 두 펌프 출력을 억제하지만 요청 모드를 유지하므로 E0 해제 시 이전 ON이 재적용됩니다.
