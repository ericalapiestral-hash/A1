# v1.3.5 제어 입력 복구와 명령 처리 진단

Aquarium 보드는 센서와 출력 상태를 전송하지만 앱이 사용하는 목표 수온·모드·주기 설정 키는 전송하지 않습니다. v1.3.4에서 설정값 미수신 시 입력을 숨기면서 목표 수온과 주기 입력이 사라졌습니다. 모드 버튼도 선택 표시가 없어 구분하기 어려웠습니다.

v1.3.5는 목표 수온·주기 입력을 복구하고 끄기·켜기·자동 버튼을 각각 테두리가 있는 버튼으로 표시합니다. 보드에서 설정값을 받지 못했을 때 표시하는 기본 입력값은 `입력값 · 보드 설정 미수신`으로 구분합니다.

BLE 제어 요청에는 전송 중, 전송됨/설정값 확인 대기, 보드 설정값 확인됨, 적용 미확인, 전송 실패를 표시합니다. 같은 설정 키와 요청값이 새 상태 메시지에 돌아온 경우에만 설정값을 확인한 것으로 표시합니다. 5초 동안 확인하지 못하면 `전송됐지만 보드 적용 미확인`으로 바뀝니다. 뒤늦은 설정값 수신도 반영합니다. BLE 쓰기 성공만으로 앱의 실제 출력 상태를 바꾸지 않습니다.

히터·펌프의 표시 상태는 보드에서 받은 값만 사용합니다. `ht`, `sup`, `cir`은 보드 보고 상태이며 화면에는 `보드 ON/OFF`로 표시합니다. 실제 히터 가열·펌프 동작을 검증했다는 뜻은 아닙니다. 연결 진단 복사에는 제어 요청과 확인 결과도 포함합니다.

**Aquarium의 실제 명령 규격은 아직 확인되지 않았습니다.** 기존 `key=value\n` 쓰기 형식은 유지합니다. 이번 업데이트는 입력 복구와 처리 결과 구분이며, 실제 Aquarium 제어가 해결됐다고 보장하는 릴리스는 아닙니다. `con`, `cof`, `son`, `sof`, `smode`를 추측해서 앱 설정값으로 변환하지 않습니다. USB 로그나 현재 펌웨어 분석으로 실제 규격을 확인해야 합니다.

## 설치

버전은 `1.3.5+9`이며 v1.3.1~v1.3.4와 같은 키로 서명합니다. 해당 버전 위에 앱을 삭제하지 않고 설치할 수 있습니다. 사전 릴리스이므로 기존 안정 릴리스의 자동 업데이트에는 포함되지 않습니다.

## Windows B보드 로그 확인

Smart App Control이 다운로드한 로그 도구를 차단하면 보안 설정을 변경하지 않고 Arduino IDE의 시리얼 모니터를 사용합니다. Arduino IDE는 [공식 사이트](https://www.arduino.cc/en/software)에서 설치합니다.

1. B보드를 USB로 연결하고 Arduino IDE의 도구 → 포트에서 해당 COM 번호를 선택합니다.
2. 도구 → 시리얼 모니터를 열고 통신 속도를 115200 baud로 설정합니다.
3. 앱의 블루투스를 연결한 상태에서 COM 번호와 마지막 20~30줄을 확인합니다. 로그가 없거나 글자가 깨지는 경우도 그대로 기록합니다.
4. 현재 보드의 원래 소스가 없으므로 업로드 버튼은 누르지 않습니다. 저장소의 B_board.ino가 현재 LCD Aquarium 펌웨어와 같다고 확인되지 않았습니다.

이 작업 환경에서 사용자의 Windows USB에 직접 접근할 수는 없습니다. 로그가 없는 경우만으로 보드 고장이나 명령 수신 실패를 단정할 수 없습니다.

## 검증

테스트 27개와 변경 파일 분석이 통과했습니다. Aquarium 상태를 받으면서 모든 모드 버튼과 수온·주기 입력이 표시되는지, BLE 쓰기 성공만으로 실제 상태가 바뀌지 않는지, 같은 키의 설정값 수신으로 확인되는지, 확인 없는 경우 적용 미확인으로 바뀌는지, 연결 방식 변경 시 이전 요청을 취소하는지 검증했습니다. 실제 Windows PC에서의 시리얼 모니터와 B보드의 출력 동작은 아직 확인되지 않았습니다.
